# 64×64 条件 DDPM 首轮实验

日期：2026-10-19。实验只读取本地配对清单和原图，不联网；训练输出位于被 Git 忽略的 `data/ml/style_ddpm/`。

## 配置

- 数据：`data/ml/style_pairs/manifest.jsonl`，50 字、735 对；train 35 字/536 对，val 7 字/97 对，test 8 字/102 对。同字不跨 split。
- 输入：加噪目标灰度图 + 未加噪楷书灰度图，2 通道；目标书体为 4 类 embedding；预测目标噪声，1 通道。
- 预处理：按 alpha 包围盒裁切、黑字白底、等比居中至 64×64。版本 `alpha-bbox-white-v1`。
- U-Net：`64/128/192/256` 通道，22,079,617 参数；DDPM 1000 训练时间步，AdamW 学习率 1e-4，batch 16。生成对照图用 DDIM 50 步。
- 主机：Linux x86_64；2 张 RTX 3090（各 24 GB），训练用 0 号卡，测试生成用 1 号卡。四书体 batch 16 单步烟测的 PyTorch 峰值预留显存约 1.9 GiB，实际训练约 2.1 GiB。此数字不含其他进程与驱动开销。

## 结果

`run_001` 从 100 步续训至 4500 步；500 步间隔验证，`latest.pt` 可从 4500 步继续。验证损失在 3500 步最低，为 0.030565；4000、4500 步分别升至 0.030831、0.031199。0 号卡持续满载时 GPU 温度达到 90°C，且验证指标已回升，因此在 4500 步停止，本轮选用 3500 步的 `best.pt`，没有运行到 10k 上限。

完整 test 字头对照图位于 `data/ml/style_ddpm/test_best_3500/`，包含八、屮、旁、每、祓、祭、禦、蒿。每行依次为楷书源图、生成图、真实目标图。人工检查显示生成图具有部分目标书体的外观，但多数未可靠保持输入字头；当前模型**未达到可用的同字书体转换质量**。验证损失下降不能代替字头保持评估。生成图仅为实验候选，不是历史字形证据，不入真实资料库。

## 复现与后续判断

训练和评估命令见 `docs/ml_style_translation.md`。checkpoint 绑定清单 SHA-256，评估会拒绝与训练清单不一致的数据；test 从未用于训练或选 checkpoint。代码回归：`.venv/bin/pytest -q`，88 项通过。下一轮重点应扩充并审核独立字头，建立字头保持的人工/识别评估；若继续条件模型研究，可检验模型是否实际利用楷书源图，并考虑更强的结构条件。当前结果不支持直接扩大训练步数作为质量改进结论。
